# 第 1 阶段全量审查结果

## 扫描方法

外层 ZIP 中的单个 7z 成员被临时写入系统临时目录，再由 `bsdtar` 解压到管道；CSV 通过逐行读取统计。没有向项目目录写入解压后的 CSV，也没有把整张表放入内存。Python 逐单元审计在大型日志上过慢，已中止；日志改用轻量管道统计，但在本次执行窗口内仍未完成。

## v1/v2 覆盖与用途

本地证据显示 v2 交易延伸到 2017-03-31，而 v1 交易到 2017-02-28；v2 文件内部路径为 `data/churn_comp_refresh/...`，记录量也明显不同。Kaggle 竞赛讨论中，竞赛参与者说明 v2 文件是带有 3 月数据的更新文件，并建议训练时按需要使用更新版本；该内容是讨论信息，不替代正式规则。

## 版本与月份判断

目前证据不能支持“v2 包含完整历史”。v2 交易覆盖 2015-01 至 2017-03，但 v2 日志完整扫描只出现 2017-03；因此 v2 更像补充月份/刷新文件，而不是可单独替代 v1 的全历史日志。

## 推荐方案

推荐阶段 2 不再采用“v2 单独替代 v1”的方案。暂定采用“v1 历史 + v2 补充月份”的分支，但仅在精确用户覆盖、重复记录和标签窗口核对后决定是否按官方更新关系合并；在实现上仍保留 v1/v2 原始分支，禁止无依据的纵向拼接。`members_v3` 作为成员表，旧 members 不使用。

该推荐在 user_logs v2 全量扫描、用户交集和官方条款登录核对完成前仍是“待验证推荐”，不是最终冻结结论。
